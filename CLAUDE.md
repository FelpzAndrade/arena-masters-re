# Arena Masters RE — protótipo de luta em Unity

Engenharia reversa do APK Arena Masters (Nexon, desativado) para estudo e uso local, e um protótipo jogável de luta 1x1 que segue as regras reconstruídas do código original.

## Regras com o usuário
- Responder sempre em **português do Brasil**, linguagem simples, sem frases em inglês.
- Não comprar nada: só assets grátis/CC0 (KayKit, Kenney, Cartoon FX Free).
- Áudio fica para depois.
- Seguir o código original sempre que possível; quando um valor vier de tabela do servidor (GameData.zip, indisponível), estimar e dizer que é estimativa.
- Não sondar o S3 da Nexon (bloqueado pela segurança). Dados de heróis: wiki de fãs via API MediaWiki (`wiki/`).
- **Ritmo de trabalho:** ajustes visuais pequenos (cor, brilho, tempo, tamanho) fazer direto e mostrar no fim, sem parar entre etapas. Parar para perguntar só em decisões de design ou mudanças grandes (formato jogável, troca de herói, regra de combate nova).

## Regras fixas de produção
- **Shaders:** HLSL escrito à mão para URP (funcionando também no Built-in quando der), sem `.shadergraph`. Pasta `Assets/VFX/Shaders`.
- **Texturas:** geradas em Python (`tools/gen_*_textures.py`, com `tools/venv/Scripts/python.exe -I`). Sem pintar à mão; cor de personagem KayKit = troca de blocos da paleta.
- **Efeitos:** Particle System (não VFX Graph), cor HDR (acima de 1) para pegar o bloom, **no máximo 80 partículas por efeito**, **sem luz em tempo real dentro dos efeitos**. Informar o custo de cada efeito novo (partículas, desenhos).
- **Reutilizável:** efeitos e scripts desacoplados dos heróis (componentes como `EfeitoCor`, `SkillEsferaGiratoria`, `Equipamento`, `EspadaBrilho`, `HitStop`, `CameraShake`, `DamageNumber`), configurados por campos.
- **Heróis do jogo:** Axie, Spark e Cavaleiro. O **Aj é só boneco de teste** (animações do Mixamo, cena VFX_Test). O boneco de treino é cinza neutro.
- **Câmera da luta:** 55 graus, distância 16,5, FOV 33. **Alvo:** iPhone e Android médio (desempenho conta).
- **Prints:** usar a **Captura rápida** (abaixo) em vez de vários prints separados. Para efeito que só existe no Play (física, script de skill rodando), usar `VfxCapture.Fileira`/`TesteShot` no Play.
- **Docs de referência:** `unity6-project/Docs/` (specs `combate_spec.md`, `ficha_skills_referencia.md`, `design_skills.md`, imagens de referência). Fora do git.
- **Plugin oficial da Unity** (`unity@unity-agent-plugin`, skills `/unity:...`): quando existir skill oficial para o assunto (pós-processamento, física, UI, multiplayer, pacotes), usar como referência do jeito certo no Unity 6. O Unity MCP continua para o que ele já faz (ver o Play ao vivo, rodar código no editor).

## Captura rápida (sem entrar no Play)
- Menu **"Arena Masters/Captura rapida/"**: "Fileira parada", "Fileira correndo", "Cavaleiro na Skill B" e "Janela..." (escolhe herói, pose, tempo/quadro, de lado e efeito de cada lugar da fila). Código: `Assets/Editor/CapturaRapida.cs`.
- Pelo MCP: `CapturaRapida.Tirar(new CapturaRapida.Pedido { nome, titulo, fileira = { new CapturaRapida.Personagem("Cavaleiro", "Redemoinho", 0.6f) { efeito = "VFX_EsferaGiratoria", tempoEfeito = 0.4f } }, foco = 0 })` ou `CapturaRapida.Fileira("idle"|"correr", deLado)`.
- Monta os heróis no trecho mais aberto da arena salva (Prototype1x1, lightmap do bake), amostra a pose (clipes legacy do KayKit e Humanoid do Aj), simula o efeito de Resources até o instante pedido e fotografa pela câmera da luta (com o pós-processamento da arena) e por uma câmera aproximada no herói em foco. Sai uma imagem só com legenda: `unity6-project/Captures/rapida_<nome>.png` (~1,2 s).
- Poses: `idle`, `correr`, `skill1..4`/`ult` (Axie, Spark), `Redemoinho`, `GolpeChao`, `Ataque1..4` (Cavaleiro, Aj) ou o nome do clipe. Os objetos são criados com `HideFlags.DontSave` e apagados: a cena da luta não fica alterada. (Não usar cena temporária aditiva: ela descarrega o lightmap da luta.)

## Código e editor
- **Assemblies:** `ArenaMasters.UI` (`Assets/UI/Scripts`: `DamageNumber`, `ComboCounter`), `ArenaMasters.VFX` (`Assets/VFX/Scripts`, inclui `Vfx.cs` e `PosProcessamentoArena.cs`), `ArenaMasters.Herois` (`Assets/Herois/Scripts`). Direção das dependências: UI ← VFX ← Heróis; nenhum deles enxerga o Combate. **O Combate (`Assets/Prototype`) e as ferramentas de editor ficam no Assembly-CSharp**, porque usam mais de 30 classes do jogo decompilado (XModuleActor, XBuff, XGameConst...) que estão nos 3.292 scripts de `Assets/Scripts/Assembly-CSharp`. Mudar um script de VFX recompila só o assembly dele (o Assembly-CSharp não recompila se a parte pública não mudar).
- **Entrar no Play sem recarregar o código** (Project Settings > Editor > Enter Play Mode Settings: só "Reload Domain" desligado; a cena continua recarregando). Campos estáticos que guardam objetos da cena ou contadores precisam de um reset com `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` (exemplos: `Vfx.Zerar`, `DamageNumber.Zerar`, `HitStop.Clear`, `CameraShake.Clear`, `TintTela`, `LuzesBraseiros`, `DungeonDecor.Occluders`). Caches de assets (prefabs, materiais) podem ficar.
- `Assets/Editor/MedirTempos.cs` escreve no Console `[Tempo] recompilacao` e `[Tempo] entrar no Play`.
- **Unity CLI** (`%LOCALAPPDATA%\Unity\bin\unity.exe`, 1.0.0-beta) + pacote `com.unity.pipeline` no projeto: `unity status` mostra o editor aberto. O pacote 0.9.0-exp.1 falha ao iniciar no Unity 6000.5 (chama uma função proibida durante o carregamento do código); `Assets/Editor/PipelineCorrecao.cs` inicia o servidor logo depois. Apagar quando sair versão corrigida.
- O editor sem foco não roda `EditorApplication.delayCall`/`update` (fica esperando a janela ganhar foco); para algo rodar logo depois de recompilar, usar `AssemblyReloadEvents.afterAssemblyReload`.
